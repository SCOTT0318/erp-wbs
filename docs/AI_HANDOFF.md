## 최근 수정의 동작

- NAS host exporter는 `synouser --get`의 계정명·UID가 일치하는 이메일만 선택 보강하며 인증된 본인의 `NormalUser.get` v2도 로그인 시 보강합니다. 실패·빈 이메일은 기존 ERP 값을 보존합니다. NAS 작업 사용자의 CLI 조회 권한과 실제 이메일 반영은 미검증입니다.
- API 시작/관리자 수동 동기화는 180초 이내의 키 보호 목록만 사용합니다. 로컬/다른 NAS/사용 중지/UID 불일치 계정을 건드리지 않고 관리자 수동 부서·직급·사번을 유지합니다. 장애는 관리자 화면에 표시하고 기존 목록과 로컬 로그인은 유지합니다.
- 최초·만료 암호(DSM 409/410)는 ERP 로그인 카드에서 `Auth.reset` v6로 변경하고 새 비밀번호로 재로그인합니다. 변경 불허 408·OTP·비밀번호 정책은 DSM이 결정하며 실제 암호 변경은 사용자 직접 입력이 필요합니다. 공개 DSM 로그인 번들에서 API 계약을 확인했으며 모의 서버 테스트만 통과했습니다.
- 로그인 장애는 DB 경계에서 확인한 `503/database_unavailable`, ERP/API 서비스 불가, 연결 실패·시간 초과를 구분합니다. NAS 계정/OTP 오류 코드는 유지하며 브라우저가 DB 원인을 추측하지 않습니다.
- 로그인과 공용 오류 화면은 그라데이션 배경과 우측 카드로 정리했고 배경 심볼·원 장식을 제거했습니다. 모바일 중앙 카드·회사 로고·파비콘을 유지합니다.
- 모든 앱 서비스에 `pull_policy: build`를 적용했습니다. Nginx는 `index.html`에 
o-cache, must-revalidate`를 보내 새 자산 참조를 재검증합니다.
- `scripts/rebuild-nas-app.sh`는 현재 `tempchain-erp` 앱만 빌드·재생성하고 health/실행 이미지 일치를 검사합니다. 독립 DB의 ID·시작 시각·마운트 불변도 확인하며 스크립트 자체의 NAS 실행 완료는 기록되지 않았습니다.

## 스키마·계정·백업 계약

- 표식은 `tempchain-postgres-v1`, 현재 코드 스키마는 **v8**입니다. 시작 시 지원 버전을 순서대로 이관하며 표식 없는 DB와 더 최신 스키마는 거부합니다. 다른 DB를 임의로 연결·이관하지 않습니다.
- v5는 NAS 이름/관리자 직급·사번, v6는 거래처 담당 부서·변경자·삭제 기록, v7은 `users.department_managed`·`sessions.last_seen_at`입니다. 관리자가 부서를 명시 저장하면 미지정(null)도 재로그인 후 보존합니다.
- 본인 부서만 변경하면 현재 세션은 유지하고 다른 세션을 폐기합니다. 역할·인증 방식·활성 상태 변경은 전체 세션 폐기 정책을 유지합니다. heartbeat는 활동 시각만 갱신하고 만료는 연장하지 않습니다.
- 빈 DB 최초 시작에는 12~128자의 `ERP_NODE_ADMIN_PASSWORD`가 필요하며 기본 ID는 `admin`, 기본 암호는 없습니다. 환경변수 변경으로 기존 계정 암호가 재설정되지 않습니다.
- 로컬 ERP 새 암호는 12~128자입니다. NAS 안내는 2026-09-15 확인 정책(최소 6자·숫자 포함·사용자 이름/설명 제외)이며 최종 판정은 DSM이 합니다. OTP 입력란은 
as_otp_required` 응답 때만 표시합니다.
- 전체 `pg_dump`는 설정된 DB를 대상으로 하며 다른 DB·클러스터 역할·NAS 파일은 포함하지 않습니다. UI 복원은 v8 호환 스키마/테이블·서명이 필요하고 이전 백업은 별도 이관용으로 원본을 보존합니다.
- NAS `erp-db/managed`와 `.signing-key`·기존 덤프·실패한 partial 사본을 보존합니다. unsigned SQL 업로드를 실행하지 않으며 실제 운영 복원은 수행하지 않았습니다.
- 
pm run nas:backup`과 `scripts/backup-nas-postgres.sh`는 이전 DB 주소/컨테이너에 의존하는 보존 도구입니다. 현재 독립 운영 DB 대상으로 검증되기 전에는 실행하지 않습니다.

## NAS 재빌드 후 반드시 확인할 사항

1. [독립 DB 안내](STANDALONE_DATABASE.md)의 앱 전용 `tempchain-erp`와 직접 생성한 `tempchain-erp-database`를 사용하고 환경 파일·데이터·키를 보존합니다.
2. host 예약 작업과 `identity.json` 생성 시각을 확인하고 180초 이상 health와 갱신을 관찰합니다. 이미지 빌드는 외부 스냅샷을 생성하지 않으며 root/container exporter 예약을 중복 등록하지 않습니다.
3. Web Station 기존 포털 연결, HTTPS API, 실제 NAS 로그인·OTP·이메일·부서 동기화를 각각 확인합니다. 실제 암호 변경은 전용 테스트 계정 준비가 필요합니다.
4. 새 운영 DB의 v7 상태, 백업 폴더/키 권한, 수동·시간별 백업을 확인합니다. 과거 [재생성 점검](NAS_RECREATE_CHECK.md)은 당시 진단 근거이며 그 문서의 통합 DB 전환 절차는 현재 구성에 적용하지 않습니다.

빌드·테스트 개수와 브라우저 미검증 범위는 [검증 기록](VALIDATION.md)에서 관리합니다. 업무 홈·접속 인원·업무 부서 선택의 당시 로컬 브라우저 검증은 5174 연결 거부로 보류됐으며 서버를 임의 실행하지 않았습니다.

- 프로필 계정 정보는 일반 텍스트로 표시하고 수정 버튼에서 이름/이메일 모달을 엽니다. 사진 적용 후에는 별도 사진 저장 버튼으로 저장합니다. 취소/ESC 후 다시 열면 저장된 값을 불러옵니다.

- 프로필 이미지는 상단 34px, 내 정보 112px 범위에 비율 유지로 표시하며 원형 장식을 제거했습니다. 사진 편집은 전체 맞춤 기준 10~400%이며 저장 경계와 투명 체크무늬는 편집기에만 표시합니다.

- 사진 편집기는 저장 사진이 없으면 기본 로고를 자동 로드합니다. 비밀번호 모달의 상세 NAS 정책 설명을 제거했으며 공유폴더/NAS는 새 비밀번호 재로그인 안내로 표시합니다(외부 세션 일괄 강제 종료는 보장하지 않음).
사진 편집 모달의 기본 프로필로 변경 버튼은 기본 로고와 초기 배율을 불러옵니다.
