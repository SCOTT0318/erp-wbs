# ERP WBS 관리 안내

갱신일: **2026-10-13**. 현재 기준은 [메인 HTML](../index.html)과 [기반 준비 데이터](../js/wbs-foundation.js). 이 페이지는 ERP 업무 입력 화면이 아닌 정적 계획·현황 기록이다.

## 현재 파일과 기록 기준

- `index.html`: 현재 상태, 날짜별 작업·배포·검증 기록과 두 탭의 구조
- `js/wbs-foundation.js`: 현재 20개 기반 준비 점검의 설명·산출물·수용 기준·상태·근거
- `js/wbs.js`: 진행률·요약·탭·검색·영역/상태 필터 렌더링
- `css/wbs.css`: 반응형·인쇄 스타일
- [WBS 현황·과거 이력](WBS.md): 현재 요약과 날짜별 과거 근거
- `js/wbs-data.js`: 과거 113개 업무 범위·24% 기록. 현재 화면의 점검 원본과 분리 보존

현재 ERP 범위는 별도 저장소의 [프로젝트 현황](../../tempchian-erp/erp-docs/md/PROJECT_STATUS.md), [검증 상태](../../tempchian-erp/erp-docs/md/VALIDATION.md), [인수인계](../../tempchian-erp/erp-docs/md/AI_HANDOFF.md)를 대조한다. 과거 6%·24%와 제거된 업무 구현은 당시 이력으로만 보존한다.

## 진행률 산정

| 표시 | 현재값 | 산정·해석 |
| --- | --- | --- |
| 프로토타입 기반 준비 | **70% · 14/20개** | 각 점검 1점. 명시된 수용 기준을 충족한 `done`만 1점, `in_progress`·`planned`는 0점 |
| 점검 상태 | 완료 14개·진행 중 4개·예정 2개 | 4개 영역에 각각 5개. 이번 현황 갱신에서 상태·점수 변경 없음 |
| 전체 ERP 구축 | **약 7%** | 이전 사용자 추정치. 이번 작업에서 재산정하지 않으며 기반 준비율과 별도 |
| ERP 문서의 전체 진행률 | **미산정** | 새 업무의 요구사항·작업량·수용 기준이 미확정되어 전체 완료율 산정 근거 부족 |

항목 수·커밋 수·검사 수·코드 줄 수를 전체 ERP 진행률로 환산하지 않는다. 신규 업무의 담당자·일정·완료일·가중치는 확정 전까지 추정하지 않는다.

## 상태와 근거의 경계

- `done`은 해당 점검의 명시된 확인 조건을 충족했다는 뜻이다. 코드·격리 검사로 완료되는 점검과 실제 운영 인수가 필요한 점검을 구분한다.
- `in_progress`는 일부 구현·검증·배포 근거가 있으나 해당 수용 기준 전체는 남은 상태다. Linux NAS 저장이 확인되어도 HDD 원본 전환·운영 복원 인수까지 완료된 것으로 집계하지 않는다.
- `planned`는 필요한 구현·실행·수용 확인이 남은 상태다. 독립 실행기와 공휴일 동기화는 예정 상태를 유지한다.
- 근거에는 날짜·대상 소스·환경·배포 버전·실행 범위·제외·남은 확인을 함께 기록한다. 과거 완료의 현재 재사용 전에는 기능 제거·정책 변경·후속 미배포 여부를 대조한다.
- 소스·빌드, 격리 DB, 모의 화면, 실제 개발 HTTP, 운영 배포·읽기 확인, 실제 업무 쓰기·복원·현업 인수는 각각 구분한다. 반복 검사를 합산하거나 앞 단계 성공으로 다음 단계 완료를 추정하지 않는다.

## 2026-10-13 현재 기준

생산부 자재·제품 구성·재고/생산·완제품 출고와 변경 후 부서 백업은 10월 12일 서버 반영 기록이 있다. 현재 DB 확인 기록은 공통 7개와 업무 6개의 총 13테이블이다. 마지막 확인 운영 배포는 `20261012-backup-cleanup-r1`이며 NAS 상태 카드 단순화와 10월 13일 부서별 대시보드·문서 개편의 운영 반영은 미확인이다.

ERP 문서는 개발 전용이다. 개발 문서는 공통 13개·부서 요청 2개, 총 15개이며 운영 Docker 컨텍스트·이미지·메뉴·본문 번들에서 제외된다. 운영 `/md`·`/api/documentation`·`/api/docs`는 익명·인증 모두 404 확인 기록을 따른다. 과거 로그인 문서 공개 확인은 해당 날짜의 이력이다.

10월 13일 부서별 화면·발표형 기술 구조도·요청서 정리와 NAS 독립 개발 관리자 검증은 소스·개발 범위다. 실제 개발 프록시의 관리자 로그인·조회·로그아웃 확인이 운영 관리자 변경·백업·복원 인수를 대신하지 않는다. 사업팀 해외구매·생산(물류)팀 데이터로거 요청은 요구사항 기록이며 신규 업무 구현 완료로 집계하지 않는다.

남은 확인은 실제 업무 저장·생산/출고 수용, HDD 원본 전환·운영 복원·빈 내부 저장소의 NAS 복구, 관리자 실제 변경·백업/복원, 세 PC 독립 실행·인증서·방화벽·이전, 공휴일 API·월간 동기화다. 우선순위와 실행 일정은 마스터의 확정 근거를 따른다.

## 변경 후 확인

현재 데이터·진행률·HTML 참조·탭·검색·필터 검사는 Windows의 `scott` 환경에서 실행한다.

```powershell
& 'C:\ProgramData\miniconda3\Scripts\conda.exe' run -n scott node scripts/verify-wbs.cjs
git diff --check
```

브라우저 확인은 현재 메인과 상세 탭의 실제 렌더링, 데스크톱·모바일, 접기/펼치기·키보드·검색·필터·가로 넘침·JavaScript 오류를 점검한다. 과거 업무일지 검증기의 이전 진행률 기대값을 현재 화면 검증으로 재사용하지 않는다. WBS 검사 통과는 Git 게시·ERP 운영 배포·현업 인수의 증거와 별도다.

금융·회계는 범위에서 제외한다. 비밀번호·토큰·환경 파일·키·실제 직원 신원·운영 자료를 WBS에 포함하지 않는다. 이번 상태 갱신은 ERP 서비스·DB·NAS 변경과 커밋·푸시·배포를 포함하지 않는다.
