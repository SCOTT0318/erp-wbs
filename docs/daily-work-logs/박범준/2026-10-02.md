### 1. 기존 로컬 개발 PostgreSQL 재사용 보호 코드 정리

- 기존 로컬 DB 컨테이너가 정상적인 관리 대상이면 다시 만들지 않고 재사용하도록 개발 실행기를 정리했습니다. DB만 실행 중인 상태와 앱/포트가 이미 사용 중인 상태를 구분합니다.
- 컨테이너가 현재 개발 폴더의 데이터 마운트·이미지·loopback 포트·DB 이름·자격 증명 조건에 맞는지 확인합니다. 다른 컨테이너나 운영 DB를 개발용으로 가져오는 경로를 허용하지 않습니다.
- 데이터 폴더와 기존 자격 증명을 보존하고, 개발 실행기의 대상 검사와 회귀를 함께 정리했습니다.
- 이 코드가 오늘 커밋된 사실과 실제 DB 포트 전환 작업의 날짜는 다릅니다. 기존 DB의 5432 전환·health/웹 응답 확인은 10월 1일 기록에 있으며 오늘 새로 전환·재시작했다고 기록하지 않습니다.

### 2. 일반 로그인 창 인증 키와 세션 경계 보완

- 일반 로그인에서 UUID v4 형식의 창 인증 키가 누락되거나 잘못되면 서버가 거부하도록 보완했습니다. 키 없이 만들어진 기존 비유지 세션은 거부·폐기합니다.
- 로그인 유지 선택과 기존 창 키에 연결된 세션은 유지합니다. 기존 NAS 재인증, 계정 변경에 따른 세션 폐기, LAN HTTP/공개 HTTPS 쿠키 경계도 보존합니다.
- 사설 LAN HTTP에서는 `crypto.randomUUID`가 없는 환경을 확인하고 `getRandomValues` 기반 UUID v4 공통 함수를 로그인·업무 폼·첨부·승인 요청에 재사용했습니다.
- 같은 입력으로 저장을 재시도하면 같은 요청 식별자를 유지하고, 입력을 바꾸면 새 식별자를 사용합니다. 실패 후 재시도의 중복 처리 방지 계약을 유지합니다.
- Origin 검사를 DB 유지보수 잠금보다 먼저 수행합니다. 복원 URL에 쿼리 문자열이 있어도 실제 라우트로 판별해 복원 요청이 자기 공유 잠금에 막히지 않도록 보완했습니다.
- 복원 도구를 실제로 실행하지 않는 격리 DB 독점 잠금 회귀로 경계를 확인했습니다.
- 대표 근거: [authentication.ts](../../../../tempchian-erp/erp-api/src/authentication.ts), [sessions.ts](../../../../tempchian-erp/erp-api/src/sessions.ts), [app.ts](../../../../tempchian-erp/erp-api/src/app.ts), [random-id.ts](../../../../tempchian-erp/erp-web/apps/web/src/random-id.ts), [auth.ts](../../../../tempchian-erp/erp-web/apps/web/src/auth.ts).

### 6. 사이드바 상태를 보관하고 홈·공통 메뉴 위치 정리

- 전체 사이드바 펼침/접힘과 공통 업무 그룹 펼침/접힘을 서로 다른 1년 쿠키로 저장합니다. 새로고침·재방문·영구 쿠키를 전달한 새 브라우저 문맥에서도 복원합니다.
- 쿠키는 Path=/·SameSite=Lax를 사용하고 HTTPS에서 Secure를 적용합니다. 누락·잘못된 값·브라우저 차단은 기본 표시로 처리하며 인증 쿠키를 건드리지 않습니다.
- 메뉴 이름을 “공통 업무”로 바꾸고 제목 버튼으로 그룹을 접고 펼칩니다. 홈은 공통 업무에서 선택한 부서 메뉴 아래로 이동해 한 번만 표시합니다.
- 생산부·기술개발부·사업부의 기존 메뉴 권한을 유지합니다. 부서 미배정·부서 조회 실패·업무 권한이 없는 경우에도 홈은 유지합니다.
- 모바일에서는 실제 보이는 버튼·링크만 포커스 대상으로 사용합니다. 열림 애니메이션 때문에 포커스가 BODY에 남던 초기 실패를 보완했고 Tab/ShiftTab·Escape·버튼 복귀를 확인했습니다.

### 10. 검색 인덱스와 선택적 검색 성능 확인

### 12. 내부 백업 다운로드·업로드와 개발 백업 도구

- 내부 백업 다운로드를 단순 링크 대신 공통 인증 다운로드 함수로 연결했습니다. 일반 로그인에서도 창 인증 키·인증 헤더를 전달해 다운로드합니다.
- 다운로드는 바이너리 응답 형식과 명시된 Content-Length의 실제 완료 길이를 확인합니다. JSON 성공 응답이나 중간에 끊긴 파일을 백업 파일로 저장하지 않습니다.
- 안전한 파일명·blob·진행/실패·401 로그인 복귀를 처리합니다. 업로드의 성공·실패·과대 입력 뒤에도 파일 입력을 초기화해 같은 파일을 다시 선택할 수 있습니다.
- 서명 `.erpbackup`을 업로드하면 검증 후 내부 목록에 추가합니다. 다운로드는 읽기 동작이며 업로드는 현재 DB를 복원하거나 바꾸는 동작과 분리합니다. 서명·해시·크기·아카이브 검증을 유지합니다.
- Windows 개발은 기존 개발 백업 폴더와 관리된 Docker PostgreSQL 도구를 사용합니다. 다른 DB를 도구 대상으로 삼지 않도록 Docker 주소·이미지·마운트·포트·DB 조건을 검사합니다.
- 실제 개발 DB 49개 테이블·221,041바이트 덤프를 생성·다운로드·재업로드·재다운로드했고 덤프 내용의 동일성과 DB 감사 건수 보존을 확인했습니다. 복원과 서비스 재시작은 수행하지 않았습니다.
- 해당 백업과 키는 Git 제외 저장소에 보존하고 보고서·HTML에 넣지 않습니다.

### 13. HDD 원본·NAS 사본 계약과 전체 이력 백업 검증

- 백업 하나를 만들거나 업로드하면 내부 HDD 원본을 먼저 완성하고 NAS에 사본을 저장하는 설정과 보호 코드를 구현했습니다. NAS 사본 실패가 내부 원본 성공을 숨기지 않도록 상태를 분리합니다.
- HDD 연결은 실제 ext4·rw·정확한 UUID·준비된 원래 서명 키·독립 경로를 확인한 뒤 허용합니다. 미마운트된 로컬 폴더, 시스템 디스크의 다른 경로, 별칭·중첩 경로를 정상 HDD로 취급하지 않습니다.
- NAS 연결은 실제 CIFS/NFS 목적지·열린 디렉터리 마운트·쓰기를 확인하고 기존 NAS 키의 일치를 검사합니다. 키 없는 빈 저장소에는 첫 사본 저장 때 원래 내부 키의 사본을 기록합니다. 원래 키를 보존하며 NAS의 다른 기존 키를 덮어쓰지 않습니다.
- 관리자에는 내부 백업 목록·다운로드·업로드와 NAS 연결 상태만 제공합니다. NAS 모드의 외부 파일/폴더 조회·다운로드·설정·수동복사 API는 404로 차단합니다.
- NAS 모드 전의 레거시 외부 설정·자동 사본 계약은 별도로 보존합니다. 오늘 중간에 구현한 외부 파일 목록은 최종 요구에 따라 현재 화면에서 제거됐습니다.
- `pg_dump`는 해당 DB 전체이며 테이블·스키마 제외 필터가 없습니다. 격리 DB에서 ERP 49개와 별도 스키마 이력 1개, 총 50개 테이블을 서명 manifest에 포함함을 확인했습니다.
- 활동/신청/기술/컨테이너 이력·실적·첨부·발행본·개인 기록 관련 10개 테이블에 fixture 행을 넣고 snapshot 행 수를 확인했습니다. 관리자 조회에서 제외된 개인 기록도 DB 백업에는 포함됩니다.
- 전체 이력 회귀의 DB 행·manifest 검사는 격리 PostgreSQL이지만 Windows의 pg_dump/pg_restore 아카이브 전송은 대체 도구를 사용했습니다. 이 회귀를 실제 운영 아카이브 생성·복원이나 실제 NAS 저장 성공으로 기록하지 않습니다. 앞선 실제 개발 백업 전송과도 별도 검사입니다.
- 다른 DB·클러스터 역할·NAS 파일·서버 환경 파일은 이 DB 백업에 포함되지 않습니다.
- 코드 표식과 스키마 v9, 기존 서명 v8/v9 복원·인덱스 재구축·세션 폐기·실패 롤백·DB 유지보수 잠금 계약을 유지합니다. 서명 없는 SQL을 UI에서 실행하는 기능은 추가하지 않았습니다.
- 대표 근거: [backup-storage.mjs](../../../../tempchian-erp/scripts/backup-storage.mjs), [docker.mjs](../../../../tempchian-erp/scripts/docker.mjs), [external-backups.ts](../../../../tempchian-erp/erp-api/src/external-backups.ts), [전체 이력 집중 로그](../../../../tempchian-erp/erp-docs/archive/2026-10-02-admin-schedules-nas/api-backup-focused.txt), [DB·백업 안내](../../../../tempchian-erp/erp-docs/DATABASE_README.md).

### 14. 관리자 데이터·설명·메뉴·번호 페이지 정리

### 16. 관리자 홈에 전체 업무 일정 집계

- 삭제한 홈의 구성원·활동 패널 공간을 업무 달력과 선택일 상세에 사용하도록 넓혔습니다. 현재 접속·활성 계정·운영 부서·활성 거래처 지표는 유지합니다.
- 생산 주문만 보던 일정에서 15개 업무 테이블의 명시 날짜·기간을 집계합니다. 생산 납기/계획/실적, 신청 희망일·가능일, 출고·회수, 입출고·로트 제조/유효일, 실사·재작업, 챔버 예약·가동중지·교정, 샘플 보관 기한 등을 표시합니다.
- 완료된 처리일도 포함하며 취소·반려와 연결 원장 사본의 중복은 제외합니다. 등록 시각을 일정으로 추측하거나 개인 메모·알림 본문을 공개하지 않습니다.

### 19. SSH 서버 저장소와 NAS 공유의 실제 확인

- 승인된 SSH에서 서버 디스크·기존 백업·마운트 상태를 읽기 전용으로 확인했습니다. 2TB ext4 HDD는 미마운트였고 기존 내부 백업 볼륨·외부 사본·키는 보존했습니다.
- 서버에는 CIFS/NFS 마운트와 클라이언트 도구가 없었습니다. SMB 포트는 응답했고 NFS 포트는 응답하지 않았습니다. sudo는 대화형 인증이 필요했습니다.
- 실제 helper가 만든 셸의 문법과 시스템 디스크 폴더에 대한 HDD UUID 거부 검사 2개를 통과했습니다.
- Alpine의 BusyBox는 필요한 realpath 옵션을 지원하지 않았습니다. 최초 5 통과·2 실패를 조건별 보안 성공으로 인정하지 않고 도구 전제 실패로 보존했습니다.
- 대안으로 Ubuntu 호스트의 uutils coreutils 0.10.0과 단일 임시 폴더·합성 키를 사용해 경로·UUID/파일시스템/rw·빈 HDD·키 크기/권한·링크·별칭·인용 조건 7개를 통과했습니다. findmnt만 모의이며 실제 HDD 준비 검사가 아닙니다. 정확한 임시 경로·소유자·삭제를 확인했습니다.
- NAS 장비 모델·DSM 버전과 공유 생성은 마스터 제공 정보입니다. 기존 비공개 설정의 전용 계정으로, 기존 HTTPS 호스트/SNI/포트/인증서 검증을 유지하고 지정한 NAS로 TCP를 고정해 로그인 1회·해당 공유 정보 조회·로그아웃을 성공했습니다.
- NAS에서 공유 존재·디렉터리·읽기/쓰기 권한을 실제 확인했습니다. 비밀값을 출력하거나 환경 파일·계정·공유 파일을 변경하지 않았습니다.
- 이 결과는 DSM 조회 권한이며 서버 SMB 마운트·실제 파일 쓰기·백업 복사 성공을 뜻하지 않습니다. 실제 계정명·사설 주소·SSH 접속 문자열·HDD UUID·환경값은 공개 WBS/HTML에 복사하지 않습니다.
- 대표 근거: [저장소 검사 결과](../../../../tempchian-erp/erp-docs/archive/2026-10-02-admin-schedules-nas/storage-guard-tests.txt), [Ubuntu 임시 회귀](../../../../tempchian-erp/erp-docs/archive/2026-10-02-admin-schedules-nas/storage-guard-tests-host-fixture.txt), [NAS 비밀 없는 결과](../../../../tempchian-erp/erp-docs/archive/2026-10-02-admin-profile-photo/nas-share-check-result.json).

## 이슈 및 확인 사항

1. 최신 전체 API는 150개 중 137 통과·1 실패·12 제외로 전체 성공이 아닙니다. Windows의 레거시 외부 디렉터리 고정 계약에서 200 기대가 503을 받는 실패가 남았습니다. Linux 보안 경로를 약화시키거나 실패를 삭제해 통과로 바꾸지 않았습니다.
2. 초기 Docker 원본은 6 통과·2 실패인데 일부 초기 요약 문서는 8/8로 기록돼 있습니다. 이번 기록은 원본 결과와 별도 최종 후속 13/13을 구분하며 초기 원본을 성공으로 바꾸지 않습니다.
3. Alpine BusyBox 도구 전제 실패를 보안 조건별 성공으로 계산하지 않습니다. Ubuntu 임시 회귀 통과는 실제 디스크/NAS 마운트 검증이 아닙니다.
4. 실제 개발 브라우저 연결은 helper 초기화/프로세스 종료 오류로 실패했습니다. 별도 Edge headless의 빌드 파일·가짜 계정·모의 API 검사는 실제 자료·직원 인수·운영 배포 검증을 대신하지 않습니다.
5. 서버 sudo는 대화형 인증이 필요하며 2TB HDD와 NAS는 서버에 마운트되지 않았습니다. NAS 로그인/공유 권한 성공만으로 관리자에 실제 NAS 사본 저장 완료를 표시할 수 없습니다.
6. 외부 백업 파일 탐색은 오늘 최종 NAS 요구에서 제거됐습니다. 과거 중간 화면·회귀 결과를 현재 기능으로 기록하지 않습니다.
7. 기존 개인 메모·알림·부서 대시보드의 전일 구현과 오늘의 보호·검색·달력 후속 개선을 구분합니다. 실제 DB 5432 전환도 전일 작업입니다.
8. 개인 사진·업무 데이터·환경 파일·원래 키·기존 백업·DB 볼륨을 보존했습니다. 공개 HTML에는 실제 계정명·사설 접속 문자열·비밀번호·토큰·환경값·덤프·키·개인 자료를 복사하지 않습니다.
9. 현재 WBS의 전체 진행률 6%는 기존 관리 추정치입니다. 오늘 검사 수·코드 줄 수·커밋 수로 새로운 진행률·완료일·현업 인수 완료를 추정하지 않습니다.

## 다음 업무

- [DB·백업 안내](../../../../tempchian-erp/erp-docs/DATABASE_README.md)에 기록된 HDD 읽기 전용 확인→정확한 UUID 마운트→기존 원본·키 유지 복사/비교→NAS SMB 마운트/권한→마스터 앱 반영 순서로 실제 저장소를 준비합니다.
- 실제 HDD/NAS에 백업 원본·사본·같은 키가 남는지 확인하고 사본 실패 때 내부 원본 성공과 오류 안내를 구분하는 실제 시나리오를 확인합니다.
- 최신 운영 코드 반영 이후 실제 직원 권한·NAS/OTP·업무 흐름과 운영 복원·검색 성능을 별도 검증합니다. 서비스 시작·중지·교체는 마스터가 수행합니다.
- 이 상세 기록을 erp-wbs에 전달해 아래 HTML/근거 갱신 요청을 수행합니다.

### erp-wbs에 전달할 기록 요청

1. 오늘 날짜는 Asia/Seoul 2026-10-02입니다. 이 파일 전체를 읽고 기존 10월 1일 기록과 중복을 합치되 날짜별 과거 근거는 보존합니다.
2. `docs/daily-work-logs/박범준/2026-10-02.md`에 상세 기록을 보관하고 `docs/WBS.md`와 `js/wbs-data.js`의 관련 항목에 오늘 구현·검증·남은 수용 조건을 연결합니다.
3. **HTML에 실제 내용을 기록합니다.** 메인 `index.html`에서 10월 2일 요약·검사 한계·남은 서버 작업이 보여야 하며 상세 내용도 HTML로 읽을 수 있어야 합니다. Markdown 링크 추가만으로 완료 처리하지 않습니다.
4. 기존 메인 HTML의 미커밋 변경을 먼저 확인하고 보존합니다. 상세 HTML을 별도 파일로 만드는 경우 메인에서 연결하고 기능별 변경·단계별 검사·미완료 범위를 충분히 포함합니다.
5. WBS 진행률·완료일을 새로 추정하지 않습니다. 소스/격리 검사 착수 근거가 생긴 항목은 수용 기준과 대조해 진행 중으로 기록하되 현업·운영 미검증을 done으로 만들지 않습니다.
6. NAS 실제 계정·사설 주소·SSH 문자열·환경값·원본 덤프·키·개인 자료는 공개 HTML에 넣지 않습니다. 비밀 없는 boolean 검사와 기능 설명을 사용합니다.
7. WBS 검증기, HTML 링크/앵커·표시·검색/탭/필터·반응형·diff를 확인하고 반영된 파일과 남은 미검증을 보고합니다. 기존 운영 서비스·DB를 변경하거나 커밋·푸시·배포하지 않습니다.
