### 검사 집계와 실제 실행 경계

- 최신 전체 API **150개 = 137 통과 + Windows 레거시 외부 API 1 실패 + Linux 전용 12 제외**입니다. 전체 성공이 아닙니다. 초기 전체 120/123/130개 실행의 외부 백업 8개 실패는 과거 실행으로 보존하며 최신 실패 수와 혼합하지 않습니다.
- 초기 Docker **원본 6 통과·2 실패**와 일부 초기 문서의 8/8 요약 불일치를 기록합니다. 후속 **13/13**은 별도 Node 모의 실행기 회귀이며 운영 Docker 기동 성공 근거가 아닙니다.
- 후속 집중 백업 **8/8**, 일정 **10/10**, Linux 파일 검사 **17 통과·Windows 전용 1 제외**, 웹 **68/68**, 관리자 모의 Edge **17/17**, 프로필 후속 app API **22/22**·Edge **13/13**을 실행별로 구분합니다. 프로필 후속은 전체 API 재실행이 아닙니다.
- 실제 개발 백업 **49개 테이블·221,041바이트**의 생성·다운로드·업로드·재다운로드 동일성을 확인했습니다. 복원·서비스 재시작은 하지 않았습니다. 격리 전체 이력 50개 테이블 회귀의 Windows 아카이브 전송은 대체 도구이며 운영 덤프·복원이 아닙니다.
- NAS 전용 계정의 **DSM 로그인 1회·대상 공유 존재/디렉터리/읽기·쓰기 권한 조회·로그아웃**은 실제 확인했습니다. 공유 조회와 서버 SMB 마운트·실제 파일 쓰기·사본 저장은 다릅니다.
- 2TB HDD와 NAS는 서버에 미마운트입니다. SSH 셸 검사 2개와 Ubuntu 임시 회귀 7/7은 합성 키·모의 findmnt를 사용했습니다. Alpine BusyBox 초기 5 통과·2 실패는 도구 전제 실패로 보존하며 실제 디스크 준비 성공으로 보지 않습니다.
- 38개 개발 인덱스 valid/ready 확인은 READ ONLY catalog 조회입니다. 격리 5,001건의 단일 검색 4.192ms는 운영 성능 목표 달성이 아닙니다. 파일별 줄 수 감소는 모듈 분리 효과이며 전체 코드량·진행률 감소 산식이 아닙니다.

### 전일과 남은 운영 작업

DB의 실제 **5432 전환은 10월 1일**이고 오늘은 재사용 보호 코드 정리입니다. 로그인 시간 정책·메모/알림·부서 대시보드의 최초 구현을 오늘 작업으로 다시 계산하지 않습니다. 관리자 사진은 기존 편집기를 다시 연결했으며 실제 개인 사진 변경 검사는 아닙니다. 외부 백업 파일 탐색은 최종 NAS 요구에서 제거됐으므로 중간 화면을 현재 기능으로 표시하지 않습니다.

남은 순서는 **HDD 기존 자료 읽기 전용 확인 → 정확한 UUID 마운트 → 기존 원본·키 유지 복사/비교 → NAS SMB 마운트·권한 → 양쪽 저장·사본 실패 복구 → 마스터의 서비스 반영**입니다. 이어 실제 직원 NAS/OTP·업무 처리·공식 서식·재고 대사·운영 복원·운영 검색 성능을 확인해야 합니다. 이번 WBS 반영에서는 운영 서비스·DB·NAS 설정을 변경하거나 커밋·푸시·배포하지 않습니다.

이번 WBS 결과 검증: `scripts/verify-wbs.cjs`의 데이터·HTML 참조·탭·검색·필터 검사와 `scripts/verify-work-log.cjs`의 원문 보존·19개 작업·4개 표·링크/앵커·공개 리터럴 검사가 통과했습니다. 별도 Edge에서 1440px·390px 메인/상세 HTML·목차·탭/영역/상태/검색·가로 넘침·페이지 오류를 검사하고 캡처를 확인했습니다. 이 검증은 WBS 기록 화면이며 ERP 운영 검증을 새로 수행한 것이 아닙니다.
