# TempChain ERP WBS

기존 진행률 기준일: **2026-09-21**

요청 범위 정리일: **2026-09-23**

2026-09-29 현재 전체 진행률: **5%** (기존 기준선 3%에서 2%p 증가)

## 현재 상태와 산정 원칙

- 전체 ERP 기준 진행률은 2026-09-21 기존 기준선 **3%**에서, 2026-09-29 확인된 구현 진척을 반영해 **5%**로 갱신합니다. 증가분 **2%p는 마스터 요청에 따른 보수적 관리 추정치**이며 세부 항목 수나 신규 가중치의 합계가 아닙니다.
- 기존 구현 기반 **18개**는 `완료 기반`, 신규 상세 작업 **95개** 중 생산부 33개·사업부 20개·기술개발부 12개, 합계 **65개**는 `진행 중`, 공통 기반·운영 **30개**는 `예정`입니다. 전체 WBS는 **113개**, 업무 영역은 **19개**입니다.
- 신규 항목의 요구사항·수용 기준은 현업 확인이 남은 **초안**입니다. 항목 수를 진행률로 환산하지 않으며, 잔여 95%를 항목별로 임의 배분하지 않습니다. 일정·담당자·우선순위·완료일도 확정 전입니다.
- 기존 자재·재고, 직렬화 컨테이너, 생산지시 기능은 `기반 완료`입니다. 아래 신규 작업의 부서 간 연계, 자동 반영, 현업 인수나 운영 배포 완료를 의미하지 않습니다.
- 금융·회계 업무는 범위에서 제외합니다. 비밀번호, 토큰, 환경 파일 내용, 실제 계정과 운영 데이터는 WBS에 넣지 않습니다.

## 2026-09-29 ERP 작업 반영

`tempchian-erp`의 **4786021** 커밋과 `erp-docs/DEPARTMENT_WORKFLOWS.md`의 65개 WBS 대응표를 대조했습니다. 생산부에는 신청 접수·계획·재작업, 로트·검수·예약·실사·기간 대사, 기준정보·컨테이너 인계가 구현됐습니다. 사업부에는 구매·생산 의뢰·출고 신청과 부서 지정 승인, Excel/PDF 발행·첨부·이력이 구현됐습니다. 기술개발부에는 챔버 예약·충돌 검사, VIP 샘플 이동·시험·결과 관리가 구현됐습니다. 이 65개는 구현 대응 단계이므로 `진행 중`으로 표시합니다.

근거는 ERP 저장소의 `erp-docs/VALIDATION.md`와 `erp-docs/archive/2026-09-29-departments/README.md`입니다. 같은 날 **4b15f59** 커밋에서 사용·운영 문서도 통합 정리했습니다. 세 워크스페이스 빌드·린트, 신규 부서 테스트 22개와 격리 브라우저·출력 검사는 통과했습니다. 전체 API 테스트는 104개 중 96개 통과·기존 Windows 외부 백업 관련 8개 실패이며 Docker 실행기 시험 8개도 실패했습니다. 원격 Ubuntu 데모 컨테이너와 공개 HTTPS 응답은 확인했으나 실제 사용자 로그인·업무 승인·백업 생성·복원은 확인하지 않았습니다. 공식 서식 승인, 현업 인수, 기존 재고의 로트 이관·실물 대사, 실제 장비와 운영 배포는 남아 있습니다. 따라서 신규 65개를 완료로 처리하지 않았습니다.

## 부서 간 연결과 결정 대기

- 사업부 **생산 의뢰 → 생산부 생산 계획·지시·실적 → 사업부 결과 회신**.
- 사업부 **컨테이너 출고 신청 → 생산부 가용성 확인·개체 예약·출고 → 사업부 실출고·회수 확인**.

- 기술개발부 시험 결과와 완제품 출하 판정의 연결은 **검토 후보**이며, 자동 차단·자동 재고 반영 등은 업무 규칙 확인 후 결정합니다.
- 공통 ID, 상태 전이, 승인권자, 정정·역거래, 중복·동시 처리, 부서 간 조회 범위와 알림 규칙을 먼저 합의합니다.
