  • 생산부·사업부·기술개발부의 기존 전용 업무 화면과 공통 거래처·자재·재고·판매 기능 전체 제거
  • 메뉴를 감추는 방식에 그치지 않고 연결된 화면, 라우터, API 등록, 업무 로직, 입력·조회 보조 코드, 업무 타입 정의까지 정리
  • 생산 자재·재고 이동·컨테이너·출고·주문·생산 결과, 생산 의뢰·출고 신청·구매 신청·구매 관리·실사·생산 계획·재작업 관련 코드 제거
  • 기술개발의 챔버·VIP 샘플·예약·시험·품질 관련 화면과 처리 코드 제거
  • 업무 문서·첨부·부서 결재·보고·업무 데이터 관리, 업무 검색·알림·업무 대시보드 및 업무 일정 연결 제거
  • 제거한 기능에만 종속된 SQL·마이그레이션·검색 인덱스 생성·알림 배포와 전용 테스트 정리
  • 기존 구현 이력과 현재 제공 기능의 차이를 문서에 반영하고, 삭제된 업무를 구현 완료 항목으로 다시 집계하지 않도록 현재 기준 명시
2. 공통 계정·인증·개인 기능 중심으로 ERP 구성 정리
  • 로그인·로그아웃·프로필·계정·부서·개인 메모·현재 접속 현황·백업을 공통 기반으로 유지
  • 일반 ERP와 독립 관리자 앱의 기능 범위를 재정리하고 관리 기능은 관리자 앱에서 제공
  • 일반 사용자 응답에서 생산 권한·업무 공간 권한·결재자·구매 권한·거래처 부서 등 제거된 업무 전용 필드 삭제
  • 관리자 홈에서 업무 처리 건수·거래처·생산 지표와 업무 달력 제거
  • 관리자 홈을 현재 접속 인원·활성 계정·운영 부서 중심의 기본 운영 현황으로 정리
  • 현재 접속 인원은 최근 활동 시간과 동일 계정 중복 제외 기준 유지
  • 감사 기록 저장과 공통 세션 처리는 유지하고 업무 알림 자동 배포만 제거
3. 신규 DB 구조 축소와 기존 DB 시작 동작 보호
  • 신규 ERP DB를 감사 기록, 부서, ERP 표식, 개인 메모, 스키마 이력, 세션, 사용자 등 공통 7개 테이블로 구성
  • 계정용 부서 식별과 계정 마이그레이션을 업무 코드에서 분리
  • 기본 부서의 이름·코드·시스템 식별자와 변경 제한을 계정 소속 관리 계약으로 유지
  • NAS 식별자·직급·그룹·관리자 지정 부서·프로필 이미지·최근 접속·개인 메모의 저장 구조 유지
  • 제거한 업무 스키마를 신규 DB에 다시 만들지 않으면서 기존 스키마 버전 및 ERP 전용 표식 유지
  • 앱 시작 과정에 기존 업무 테이블이나 알 수 없는 테이블을 자동 삭제하는 처리 추가 없음
  • ERP 전용 표식 없는 기존 스키마와 코드보다 최신인 스키마의 시작 거부 유지
  • 기능 제거에 따른 코드 정리와 마스터가 별도로 지시한 운영 ERP DB 초기화를 구분해 기록
4. 서명된 기존 백업의 복원 호환 유지
  • 삭제한 업무 테이블은 과거 서명 백업의 호환 검사에 필요한 이름 목록으로만 유지
  • 호환 목록을 업무 화면·업무 스키마 생성·업무 마이그레이션 재도입에 사용하지 않도록 분리
  • 기존 v8·v9 서명 백업의 필수 테이블 구성과 허용된 과거 모듈의 완전한 구성을 검사하는 계약 유지
  • 일부 테이블만 있는 모듈, 알 수 없는 테이블, 다른 스키마, 중복 이름을 복원 대상으로 받아들이지 않는 검사 유지
  • 복원 전 안전 백업, 서명·내용 해시·파일 크기·ERP 표식·활성 관리자·스키마 버전 검사 유지
  • 복원 검증·개인 메모 구조 보완·세션 폐기·감사 기록을 같은 트랜잭션에서 처리하는 계약 유지
  • 알 수 없는 외부 의존성을 연쇄 삭제하지 않고 복원 실패 시 롤백하는 구조 유지
  • 내부 서명 키와 백업 비활성 상태에서도 필요한 DB 유지보수 잠금 유지
5. 같은 사내망의 DB·백엔드·프론트엔드 분리 보안 준비
  • 향후 세 컴퓨터로 나누는 운영을 위한 분리 배포 설정과 보안 조건 추가
  • API의 HTTPS 인증서·키 경로를 검사하고 두 파일이 함께 제공되지 않거나 인증서가 잘못되면 시작 중단
  • API TLS의 최소 버전을 설정하고 DB를 열거나 마이그레이션하기 전에 인증서 유효성 검사
  • 전달 헤더를 신뢰할 프록시는 명시한 사설 또는 loopback IP만 허용하고 기본값은 신뢰하지 않도록 구성
  • 전체 대역·임의 호스트·공개 IP를 신뢰 프록시로 지정하는 설정 거부
  • PostgreSQL 연결은 인증서와 접속 대상 이름을 모두 검증하는 방식 지원
  • DB 연결 URL의 임의 호스트·사용자·포트 우회 및 중복 매개변수 거부
  • API 연결과 백업·복원 명령이 같은 검증된 DB 대상과 TLS 정책을 사용하도록 공통 연결 처리 적용
  • 상속된 PostgreSQL 환경 설정이 백업 명령의 접속 대상을 바꾸지 않도록 정리
  • 분리 모드에서는 DB 인증서 검증·API HTTPS·신뢰 프록시·Secure 쿠키·정확한 HTTPS Origin을 모두 요구
  • 분리용 프록시 템플릿과 인증서·DB 접근·방화벽 적용 안내 작성
  • 현재 실행기는 동일 Docker 호스트 기준이며 실제 세 PC 이전 완료와 구분
6. 초기 관리자 암호 정책과 관리 API 경계 강화
  • 빈 DB의 초기 관리자에 적용되던 짧은 기본 암호 예외 제거
  • 모든 초기 관리자 암호에 길이 정책 적용하고 로그인 ID 형식 검사 유지
  • 초기 관리자 생성은 사용자 없는 DB에만 적용하고 재시작 시 기존 암호·비활성 상태를 덮어쓰지 않도록 유지
  • 계정 조회·수정 및 부서 생성·수정 API를 관리자 전용 경로로 이동
  • 일반 사용자에게 필요한 로그인 후 부서 목록 조회만 기존 공통 경로에 유지
  • API 진입과 변경 트랜잭션 안에서 관리자 권한 재확인 유지
  • 마지막 활성 관리자 해제, 사용 중인 부서 비활성화 등 기존 관리 보호 유지
  • 역할·활성·인증 방식 변경 시 전체 세션 폐기 유지
  • 관리자 자신의 부서만 수정할 때 현재 편집 세션을 유지하는 기존 계약 유지
  • 관리자 화면과 NAS 회귀 검사의 호출 경로를 변경된 관리 API 경계에 맞게 수정
7. 오류 페이지와 관리자 접근 제한 화면 정리
  • 오류 페이지의 로고·카드 위치를 기존 로그인 화면과 맞추도록 수정
  • 파랑·초록 배경, 왼쪽 흰 TEMPCHAIN 로고, 오른쪽 흰 카드의 데스크톱 배치 적용
  • 좁은 화면에서는 카드를 중앙에 배치하고 카드 안 로고·여백·글자 크기 조정
  • 오류 번호·짧은 제목·간단한 안내 위주로 문구 정리
  • 반복된 설명·영문 보조 문구·불필요하게 긴 안내 제거
  • 관리자 접근 제한 화면에도 같은 배치와 간결한 안내 적용
  • 로그아웃 동작·실패 안내와 화면 접근성 유지
  • 정적 오류 페이지와 관리자 접근 제한 화면의 데스크톱·경계 폭·모바일 배치 확인 기록 확보
8. 홈 월간 달력과 부서 선택 화면 구성
  • 홈에 순수 월간 달력과 개인 메모를 함께 배치하고 좁은 화면에서는 한 열로 전환
  • 연도·월 선택, 이전·다음 달 이동, 오늘 복귀, 선택 날짜 표시 제공
  • 한국 시간 기준 오늘 표시와 앞뒤 달 날짜를 포함한 월간 표 구현
  • 연도 범위 경계·월말·윤년 날짜를 처리하고 월 변경 시 선택일을 해당 월의 마지막 날짜에 맞게 보정
  • 한국 자정·브라우저 다시 활성화·탭 표시 전환 때 오늘 표시 갱신
  • 오늘·선택 날짜 상태, 날짜 버튼 설명, 선택 날짜 안내 및 이동 후 포커스 처리 적용
  • 홈 및 공통 탐색에서 활성 부서를 선택해 부서 준비 화면으로 이동하도록 구성
  • 부서 선택을 계정 소속 변경과 분리하고 계정 수정 API 호출 없이 화면 이동으로 처리
  • 부서 화면에 부서 이름·선택 필드·“현재 서비스 준비 중입니다.” 안내 제공
  • 존재하지 않거나 비활성인 부서의 직접 접속은 목록 확인 후 홈으로 이동
  • 부서 목록 로딩·실패·재조회 상태 처리와 계정 전환 시 목록 초기화 적용
  • 오래된 조회 응답이 다른 계정의 목록을 덮어쓰지 않도록 요청 세대 구분 적용
  • 삭제한 업무 일정·생산 일정 API와 달력 연결 없음
9. 경영진 메뉴 제외와 NAS 신원 계약 보존
  • 부서 탐색과 선택 목록에서 경영진 코드 및 경영진·경연진 이름 제외
  • 이름 공백·문자 정규화와 코드 대소문자를 고려해 메뉴 필터 적용
  • 실제 NAS CEO·CTO 계정·직급·신원·동기화 정보 유지
  • 경영진 메뉴 제외를 계정 삭제나 NAS 인증 해제로 확대하지 않도록 구성
  • 경영진 별도 조회 권한은 이번 변경에서 신설되지 않았음을 현재 상태에 명시
10. 요청된 ERP 전용 DB 초기화와 보안 작업 배포
  • 마스터가 지시한 준비 단계의 ERP 전용 DB 전체 초기화 수행 기록 확인
  • 초기화 후 DB 재시작과 공통 스키마 생성, DSM 계정 재등록 확인 기록 확보
  • 다른 DB·클러스터 역할·NAS 자료·백업·서명 키·환경 설정·점검 서비스는 초기화 범위에서 제외
  • DB·API의 호스트 포트 미게시와 지정 LAN 관리자 바인딩 유지
  • 공개 HTTPS 상태 확인, 인증 없는 세션 거부, 허용하지 않은 Origin·Host 차단 확인
  • 제거된 업무 경로와 당시 공개하지 않던 관리 경로의 접근 차단 확인
  • 이후 문서·관리자 후속 배포에서는 DB를 다시 초기화하지 않고 앱만 교체
11. NAS 직접 로그인 유지 및 지정 검증 계정 확인
  • 보안 정비·초기화·앱 교체 과정에서 NAS 직접 인증 설정과 DSM 조회 계약 유지
  • NAS 계정 로그인은 실제 DSM 인증과 현재 계정 신원·그룹·활성 상태 재확인 흐름 유지
  • NAS 연동 실패를 로컬 암호 로그인으로 대체하지 않는 기존 계약 유지
  • 시작·수동 동기화의 사용자·그룹·소속 조회, NAS UID·토큰 전달 및 관리자 지정 부서 보존 유지
  • 지정된 기존 지정 NAS 일반 검증 계정 NAS 일반 계정으로 LAN과 NAS 역방향 프록시의 DDNS에서 실제 로그인 확인
  • 로그인 후 세션 조회·화면 진입·새로고침·로그아웃 확인
  • 운영 계정 목록과 검증 계정 존재 확인 기록 확보
  • 입력 형식 오류는 강력 새로고침 후 사용자 로그인 성공으로 확인됐으며 개별 실패 필드는 미확보 상태로 기록
  • 개별 입력 원인이나 NAS 설정 변경으로 해결한 문제라고 단정하지 않도록 정리
12. 문서 보관 범위 정리와 MD·HTML 폴더 분리
  • ERP 기술 안내의 중복·오래된 경로·현재 상태와 다른 설명 정리
  • 프로젝트 기술 문서와 관계없는 사진·원시 출력·일일 업무일지 자료 정리
  • 기술 문서 원본을 erp-docs/md/, 생성 HTML을 erp-docs/html/로 분리
  • 인수인계·NAS 인증·배포·백업·보안·검증 안내의 경로와 상호 참조 갱신
  • 현재 제공 기능 안내와 과거 업무 구현 기록을 구분해 유지
  • 로컬 화면·검증 결과·이번 업무일지는 Git에서 제외되는 개발 자료 경로에 보관
  • 환경 파일·암호·키·토큰·개인별 비공개 값은 기술 문서와 공개 결과에 포함하지 않도록 유지

13. HDD 원본·NAS 사본 계약과 전체 이력 백업 검증
  • 백업 하나를 만들거나 업로드하면 내부 HDD 원본을 먼저 완성하고 NAS에 사본을 저장하는 설정과 보호 코드를 구현했습니다. NAS 사본 실패가 내부 원본 성공을 숨기지 않도록 상태를 분리합니다.
  • HDD 연결은 실제 ext4·rw·정확한 UUID·준비된 원래 서명 키·독립 경로를 확인한 뒤 허용합니다. 미마운트된 로컬 폴더, 시스템 디스크의 다른 경로, 별칭·중첩 경로를 정상 HDD로 취급하지 않습니다.
  • NAS 연결은 실제 CIFS/NFS 목적지·열린 디렉터리 마운트·쓰기를 확인하고 기존 NAS 키의 일치를 검사합니다. 키 없는 빈 저장소에는 첫 사본 저장 때 원래 내부 키의 사본을 기록합니다. 원래 키를 보존하며 NAS의 다른 기존 키를 덮어쓰지 않습니다.
  • 관리자에는 내부 백업 목록·다운로드·업로드와 NAS 연결 상태만 제공합니다. NAS 모드의 외부 파일/폴더 조회·다운로드·설정·수동복사 API는 404로 차단합니다.
  • NAS 모드 전의 레거시 외부 설정·자동 사본 계약은 별도로 보존합니다. 오늘 중간에 구현한 외부 파일 목록은 최종 요구에 따라 현재 화면에서 제거됐습니다.

이슈 및 확인 사항

  1. 최신 전체 API는 150개 중 137 통과·1 실패·12 제외로 전체 성공이 아닙니다. Windows의 레거시 외부 디렉터리 고정 계약에서 200 기대가 503을 받는 실패가 남았습니다. Linux 보안 경로를 약화시키거나 실패를 삭제해 통과로 바꾸지 않았습니다.
  2. 초기 Docker 원본은 6 통과·2 실패인데 일부 초기 요약 문서는 8/8로 기록돼 있습니다. 이번 기록은 원본 결과와 별도 최종 후속 13/13을 구분하며 초기 원본을 성공으로 바꾸지 않습니다.
  3. Alpine BusyBox 도구 전제 실패를 보안 조건별 성공으로 계산하지 않습니다. Ubuntu 임시 회귀 통과는 실제 디스크/NAS 마운트 검증이 아닙니다.
  4. 실제 개발 브라우저 연결은 helper 초기화/프로세스 종료 오류로 실패했습니다. 별도 Edge headless의 빌드 파일·가짜 계정·모의 API 검사는 실제 자료·직원 인수·운영 배포 검증을 대신하지 않습니다.
  5. 서버 sudo는 대화형 인증이 필요하며 2TB HDD와 NAS는 서버에 마운트되지 않았습니다. NAS 로그인/공유 권한 성공만으로 관리자에 실제 NAS 사본 저장 완료를 표시할 수 없습니다.
  6. 외부 백업 파일 탐색은 오늘 최종 NAS 요구에서 제거됐습니다. 과거 중간 화면·회귀 결과를 현재 기능으로 기록하지 않습니다.
  7. 기존 개인 메모·알림·부서 대시보드의 전일 구현과 오늘의 보호·검색·달력 후속 개선을 구분합니다. 실제 DB 5432 전환도 전일 작업입니다.
  8. 개인 사진·업무 데이터·환경 파일·원래 키·기존 백업·DB 볼륨을 보존했습니다. 공개 HTML에는 실제 계정명·사설 접속 문자열·비밀번호·토큰·환경값·덤프·키·개인 자료를 복사하지 않습니다.
  9. 전체 진행률은 WBS 업무별 상태에 따라 계산합니다. 현업 인수·운영 배포의 완료 여부는 별도로 확인합니다.
